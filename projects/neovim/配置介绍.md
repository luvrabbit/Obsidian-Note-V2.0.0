# 从头搭建 nvim12：我的 Neovim 配置介绍

本文记录我如何一步步从零搭建 nvim12 配置，同时介绍 Neovim 配置的基础知识，帮助想自己动手的人理解背后的机制。

## 第一部分：Neovim 配置基础

### 1.1 配置的本质

Neovim 启动时会读取 `init.lua`（或 `init.vim`），这个文件就是配置的**唯一入口**。配置文件的本质就是 Lua 脚本，Neovim 内嵌了一个 **LuaJIT 虚拟机**来逐行执行它。

```lua
-- init.lua：Neovim 启动时从头到尾执行一遍
require("config.options")  -- 设置编辑器选项
require("plugins")         -- 加载插件
vim.cmd.colorscheme("tokyonight-moon")  -- 设置配色
```

每一行代码都在改变编辑器的状态：设置一个选项、加载一个插件、绑定一个快捷键。配置文件不需要"编译"——它就是**每次 Neovim 启动时被 Lua VM 执行一遍的脚本**。

### 1.2 `require` 机制详解

`require` 是 Lua 加载模块的机制，不是简单的文件复制（不是 C 的 `#include`）。

```lua
local conform = require("conform")
```

它的完整流程：

1. **搜索**：遍历 `runtimepath` 下所有 `lua/` 目录，找 `conform/init.lua` 或 `conform.lua`
2. **加载**：读取文件内容到内存
3. **编译**：Lua VM 将源码编译为字节码（内存中，不生成文件）
4. **执行**：Lua VM 解释执行字节码
5. **缓存**：将返回值存入 `package.loaded["conform"]`
6. **返回**：返回模块的值（通常是一个 table）

**关键特性**：第二次 `require("conform")` 直接返回缓存，**不会重新执行文件**。这就是为什么修改插件代码后必须重启 Neovim（或 `:luafile %`）。

那 `.setup()` 执行的是什么？

```lua
local conform = require("conform")  -- 加载模块，返回一个 table
conform.setup({ formatters_by_ft = { lua = { "stylua" } } })
```

`require` 执行的是**插件的定义代码**——声明函数、变量、配置结构。`.setup()` 是模块定义好的一个普通 Lua 函数，你把参数传进去，它内部把参数合并到自己的配置中。

```
require = 把洗衣机搬进家、通上电
setup   = 按按钮设置"快洗模式"
```

两者都是在 Lua VM 中执行的普通代码，没有本质区别。`require` 多做了"找到文件 + 编译"这两步，`setup` 只是纯粹的函数调用。

### 1.3 `runtimepath` 与 `packpath`

这两个概念决定了 Neovim 去哪里找配置和插件。

**`runtimepath`**（运行时路径）：Neovim 按顺序搜索这些目录，寻找 `lua/`、`plugin/`、`syntax/` 等子目录。

查看方式：

```
:lua print(vim.inspect(vim.opt.runtimepath:get()))
:set runtimepath?
```

典型的 `runtimepath` 组成（按优先级从高到低）：

| 来源 | 示例路径 |
|---|---|
| 配置文件目录 | `~/.config/nvim12` |
| pack 目录下的 start 插件 | `~/.local/share/nvim12/site/pack/*/start/*` |
| Neovim 内置 | `/usr/share/nvim/runtime` |

**`packpath`**（包路径）：决定 Neovim 去哪找 `pack/*/start/` 和 `pack/*/opt/` 目录。

```lua
:lua print(vim.opt.packpath:get())
```

当 `vim.pack.add({ src = "..." })` 执行时，它做的是：

1. 在 `packpath` 下的某个目录中 `git clone` 插件仓库
2. 该插件的 `lua/` 目录自动进入 `runtimepath`
3. 后续 `require("插件名")` 就能找到它

**为什么你的 `lua/plugins/` 下的文件能被 `require` 到？**

因为 `~/.config/nvim12` 就在 `runtimepath` 里，所以 `require("plugins.colorscheme")` 会找到 `~/.config/nvim12/lua/plugins/colorscheme.lua`。

### 1.4 后续学习路径

- **`:help`**：Neovim 最权威的文档，对于任何插件，`:help 插件名` 通常会打开详细文档
- **GitHub README**：插件的首要文档入口，一般有 quickstart 和 API 说明
- **别人的 dotfiles**：GitHub 搜索 `neovim` + `lua`，看别人怎么写
- **看源码**：遇到问题直接读插件的 `lua/` 目录下的源码，Lua 很容易读
- **`:lua print(vim.inspect(...))`**：随时打印变量看结构，是调试的最佳手段

## 第二部分：从零到 nvim12 —— 逐步骤搭建

### Step 1：地基 —— init.lua 与基本选项

最初的几步只是建立一个干净的起点。

```lua
-- ~/.config/nvim12/init.lua
require("config.options")
```

选项文件 `lua/config/options.lua` 定义了编辑器的基本行为：

| 选项 | 值 | 作用 |
|---|---|---|
| `tabstop` | 2 | 一个 Tab 占 2 列 |
| `expandtab` | true | Tab 转空格 |
| `number` + `relativenumber` | true | 混合行号 |
| `cursorline` | true | 高亮当前行 |
| `scrolloff` | 8 | 光标上下留 8 行 |
| `ignorecase` + `smartcase` | true | 智能大小写搜索 |

`vim._core.ui2` 是 Neovim 0.12+ 的新 UI 引擎，开启后界面渲染更现代。

### Step 2：插件管理器 —— vim.pack

我选择了 Neovim 0.12+ **内置的 `vim.pack`**，而不是懒加载方案 lazy.nvim。

**为什么？**
- 零额外依赖，内置就是最好的兼容性
- 简单直接：`vim.pack.add({ src = "..." })` 一行注册
- 不需要学习插件管理器的 DSL（领域特定语言）

**自动加载机制**（`lua/plugins/init.lua`）：

```lua
for _, file in ipairs(vim.fn.readdir(vim.fn.stdpath("config") .. "/lua/plugins")) do
  if file:match("%.lua$") and file ~= "init.lua" then
    pcall(require, "plugins." .. file:gsub("%.lua$", ""))
  end
end
```

这段代码遍历 `lua/plugins/` 目录下所有 `.lua` 文件（除了 `init.lua` 自己），自动 require 它们。这意味着**新建一个 `.lua` 文件丢进去就会自动加载**，不需要在 `init.lua` 中注册。

插件版本锁定在 `nvim-pack-lock.json` 中，记录每个插件的 commit SHA。

### Step 3：配色方案

第一个插件往往是配色方案——安装即有视觉反馈，成就感来得最快。

```lua
vim.pack.add({
  { src = "https://github.com/catppuccin/nvim", name = "catppuccin" },
  { src = "https://github.com/rose-pine/neovim", name = "rose-pine" },
  { src = "https://github.com/folke/tokyonight.nvim", name = "tokyonight" },
  { src = "https://github.com/ellisonleao/gruvbox.nvim", name = "gruvbox.nvim" },
})

vim.cmd.colorscheme("tokyonight-moon")
```

安装了 4 个配色，当前使用 Tokyo Night Moon。切换只需改一行代码。

### Step 4：核心编辑体验 —— mini.nvim 全家桶

**mini.nvim** 是一个模块化插件集合，一个仓库包含约 20 多个独立模块，每个模块可单独启用。

我选择的配置策略是：**能用 mini 替代的就不用独立插件**。

这样一来，几十个独立插件（vim-surround、vim-easymotion、which-key、nvim-cmp……）被压缩成一个。好处是配置集中在一个文件、行为风格统一、减少 API 冲突风险。

启用的模块（`lua/plugins/mini.lua`）：

| 模块 | 作用 | 替代了什么 |
|---|---|---|
| `mini.icons` | 文件类型的图标 | nvim-web-devicons |
| `mini.surround` | 环绕编辑（`ys`、`ds`、`cs`） | vim-surround |
| `mini.pairs` | 自动补全括号引号 | auto-pairs |
| `mini.ai` | 自定义文本对象（`ia`、`ii`） | vim-textobj-user |
| `mini.jump2d` | 二维跳跃（EasyMotion 风格） | hop.nvim / easymotion |
| `mini.snippets` | 代码片段引擎 | Luasnip |
| `mini.completion` | 补全菜单 | nvim-cmp |
| `mini.statusline` | 状态栏 | lualine |
| `mini.cursorword` | 高亮光标下单词 | vim-illuminate |
| `mini.diff` | Git 增删标记 | gitsigns |
| `mini.cmdline` | 命令行增强 | wilder.nvim |
| `mini.pick` | 内置模糊搜索 | telescope / fzf-lua（作为备选） |
| `mini.indentscope` | 缩进指示线 | indent-blankline |
| `mini.hipatterns` | 高亮 TODO/FIXME/hex 颜色 | — |
| `mini.starter` | 启动画面 | dashboard / alpha |
| `mini.clue` | 快捷键提示浮窗 | which-key |
| `mini.sessions` | 会话保存恢复 | — |

每一步的配置模式都一样：

```lua
require("mini.icons").setup({ style = "glyph" })
require("mini.surround").setup()
-- ...
```

这就是前面说过的模式：`require` 加载模块 → `.setup()` 传入配置。

### Step 5：Treesitter —— 语法解析引擎

#### 5.1 Treesitter 是什么

传统的语法高亮基于正则表达式（`:syntax on`），只管"关键字匹配颜色"。Treesitter 解析代码生成**完整的语法树（AST）**，Neovim 知道这段代码是"函数定义"还是"if 条件"而不是"一堆文本"。

有了语法树，可以实现：
- **准确的语法高亮**（不会跨字符串边界误匹配）
- **增量选择**：`vaf` 选中整个函数
- **代码折叠**：基于语法树而非缩进
- **文本对象**：`ci` 修改条件表达式内部

#### 5.2 前置条件

Treesitter 的 parser 是 **C 动态库（`.so` 文件）**，需要编译器来构建：

```
gcc / clang（C 编译器）
make
```

Neovim 0.9+ 内置了 `vim.treesitter` Lua API，无需额外安装模块。

#### 5.3 我的配置方式

我选择**动态按需加载**，而不是常见的预装全部 parser：

```lua
vim.api.nvim_create_autocmd("FileType", {
  pattern = "*",
  callback = function(ev)
    local lang = vim.treesitter.language.get_lang(vim.bo[ev.buf].filetype)
    if lang and vim.treesitter.language.add(lang) then
      vim.treesitter.start(ev.buf, lang)
    end
  end,
})
```

工作流程：

1. 打开一个 `.py` 文件 → 触发 `FileType` 事件，filetype 为 `python`
2. `get_lang("python")` → 返回 `"python"`
3. `language.add("python")` → 检查本地是否有 `python.so`
   - 没有 → 从 GitHub 下载 C 源码 → 编译 → 存入 `~/.local/share/nvim12/`
   - 有 → 直接加载
4. `treesitter.start(buf, "python")` → 在该 buffer 上启用语法解析

对比主流方式：大多数人用 `ensure_installed` 一次性安装几十个 parser，我用时再装。启动更快，第一次打开新语言时稍等几秒编译。

#### 5.4 调试 Treesitter

```
:InspectTree       → 在新窗口中显示当前 buffer 的完整语法树
:TSModuleInfo      → 查看已安装的 parser 和模块状态
:echo vim.treesitter.language.get_lang(vim.bo.filetype)  → 查看当前语言是否被识别
```

### Step 6：LSP 语言服务

LSP（Language Server Protocol）是 Neovim 获得 IDE 能力的关键。它是一个**标准协议**，定义了编辑器与语言服务器（一个独立进程）之间的通信方式。

Neovim 通过 **JSON-RPC**（一种基于 JSON 的远程调用协议）通过 stdin/stdout 与语言服务器通信。你编辑代码时，Neovim 告诉服务器"用户改了第 5 行"，服务器返回"这行有个错误"。

我的 LSP 体系由三个组件构成：

#### 6.1 Mason —— 语言服务器的安装器

```lua
require('mason').setup()
```

**Mason 只做一件事**：帮你安装和管理语言服务器（以及 linter、formatter 等工具）的二进制文件。

**安装位置**：

```
~/.local/share/nvim12/mason/packages/
├── pyright/
├── lua-language-server/
└── clangd/
```

每个目录下就是对应的语言服务器。Mason 自动把这些二进制文件所在的目录加入 `PATH`，后续的工具能找到它们。

**使用方式**：

```
:Mason          → 打开包管理器 UI，搜索/安装/更新
:MasonInstall pyright lua-language-server  → 命令行安装
```

**重要**：Mason **只管下载安装，不管配置**。它负责让你的系统有 `pyright` 命令可用。

#### 6.2 nvim-lspconfig —— 语言服务器的配置中心

```lua
vim.lsp.enable("pyright")
vim.lsp.enable("lua_ls")
vim.lsp.enable("clangd")
```

`vim.lsp.enable`（Neovim 0.11+ 引入，替代旧式的 `require('lspconfig').pyright.setup{}`）背后做了：

1. 在 `PATH` 中查找 `pyright` 二进制（Mason 已将其加入 `PATH`）
2. 启动 pyright 子进程
3. 通过 stdin/stdout 建立 JSON-RPC 连接
4. 注册 LSPAttach 事件，通知 Neovim 该语言服务器已就绪

**三个 LSP 服务器**：
- **pyright**：Python 的类型检查、补全、跳转
- **lua_ls**：Lua（Neovim 配置用的就是它）
- **clangd**：C/C++（你的系统级开发）

#### 6.3 LSPAttach —— 入口事件

当 LSP 客户端成功 attach 到一个 buffer 时，触发 `LspAttach` 事件。这是绑定快捷键的最佳时机：

```lua
vim.api.nvim_create_autocmd("LspAttach", {
  callback = function(ev)
    local map = function(keys, func, desc)
      vim.keymap.set("n", keys, func, { buffer = ev.buf, desc = desc })
    end

    map("gd", vim.lsp.buf.definition, "Goto definition")
    map("gr", vim.lsp.buf.references, "Goto references")
    map("K", vim.lsp.buf.hover, "Hover documentation")
    map("<leader>rn", vim.lsp.buf.rename, "Rename symbol")
    map("<leader>ca", vim.lsp.buf.code_action, "Code action")
    -- ...
  end,
})
```

**这些函数实际上是向语言服务器发送请求**：

```
按 gd
  → vim.lsp.buf.definition()
    → Neovim 通过 JSON-RPC 发送 textDocument/definition 请求
      → 服务器返回文件路径和位置
        → Neovim 跳转到该位置
```

#### 6.4 格式化

conform.nvim 是格式化调度器，在保存时自动运行：

```lua
conform.setup({
  formatters_by_ft = {
    lua = { "stylua" },
    python = { "isort", "black" },  -- 先排序 import，再格式化
  },
  format_on_save = {
    timeout_ms = 500,
    lsp_format = "fallback",  -- 没有专门 formatter 时用 LSP
  },
})
```

**conform 只负责调度**，真正的格式化工具（stylua、isort、black）需要单独安装（可以通过 Mason 或系统包管理器）。

流程：
```
保存文件
  → conform 检查文件类型
    → 找到 lua = { "stylua" }
      → 调用 stylua 命令（子进程）
        → stylua 修改文件内容
          → Neovim 重新加载 buffer
```

#### 6.5 调试 LSP

当 LSP 不工作时，以下命令帮你排查：

```
:LspInfo           → UI 面板：哪些服务器在运行？attach 到了哪个 buffer？
:LspLog            → 打开 LSP 日志文件
:lua print(vim.inspect(vim.lsp.get_clients()))  → 查看所有已连接的客户端

-- 日志位置
:echo vim.lsp.get_log_path()
-- 结果：~/.local/state/nvim12/lsp.log
```

**排查思路**：
1. `:Mason` → 确认服务器已安装
2. `:LspInfo` → 确认服务器已 attach 到当前 buffer
3. `:LspLog` → 查看通信日志，搜索 `ERROR` 或 `traceback`
4. `:echo executable("pyright")` → 确认系统能找到二进制文件

### Step 7：补全

使用 `mini.completion` 提供补全菜单，`mini.snippets` 提供代码片段支持。

补全的来源包括：
- LSP 语义补全（变量名、函数名、参数）
- Treesitter 语法感知
- 代码片段（snippets）

Tab / Shift-Tab 控制补全菜单上下选择，回车确认。

### Step 8：导航与搜索

**fzf-lua**：集成 fzf 到 Neovim 中的模糊搜索工具。

```
<leader>ff    → 搜索文件名
<leader>fg    → 搜索文件内容（live grep）
<leader>fb    → 搜索已打开的 buffer
```

**oil.nvim**：以 buffer 方式编辑文件系统。打开一个目录路径，它变成一个可编辑的 buffer，可以像编辑文本一样管理文件（重命名、删除、新建）。

```
<leader>e     → 打开当前目录的 oil buffer
```

### Step 9：视觉打磨

| 插件 | 作用 |
|---|---|
| `render-markdown.nvim` | 在 buffer 中实时渲染 Markdown（标题加粗、代码块高亮） |
| `smear-cursor.nvim` | 光标移动时的平滑动画 |
| `mini.indentscope` | 每级缩进显示一条 `┃` 线 |
| `mini.statusline` | 美化状态栏，显示文件名、行号、Git 分支 |
| `mini.starter` | 启动时的欢迎画面，含 ASCII 艺术字 |

### Step 10：快捷键体系

快捷键全部定义在 `lua/config/keymaps.lua` 中。

核心快捷键：

| 键 | 作用 |
|---|---|
| `jk` | 替代 Esc 退出插入/命令行模式 |
| `<C-s>` | 保存 |
| `<C-z>` / `<C-r>` | 撤销 / 重做 |
| `<C-h>` / `<C-l>` | 上一个 / 下一个标签页 |
| `<leader>bb` | 跳转到上一个 buffer |
| `<leader>rr` | 重启 Neovim（0.12+ 内置） |
| `<C-_>` | 切换底部终端 |
| `<leader>tt` | 切换全屏终端 |
| `<leader>tn` | 新标签页 + 终端 |

终端管理有智能切换逻辑：已有终端则复用，没有则创建，可见则关闭。

**mini.clue** 替代 which-key：输入 `<leader>` 或 `[` `]` `g` 等前缀键后，显示所有可用的后续键位，200ms 延迟弹出浮窗。

## 第三部分：设计决策总结

| 决策 | 我的选择 | 备选方案 | 理由 |
|---|---|---|---|
| 插件管理器 | `vim.pack`（内置） | lazy.nvim | 零依赖，原生支持，足够满足需求 |
| 功能整合 | mini.nvim 全家桶 | 零散独立插件 | 配置集中、风格统一、减少冲突 |
| 快捷键提示 | mini.clue | which-key.nvim | 已在 mini 生态中，无需额外插件 |
| 补全方案 | mini.completion | nvim-cmp | 够用，配置简单 |
| Treesitter 安装 | 动态按需 | ensure_installed | 启动更快，不需要的语言不装 |
| LSP 启用 | `vim.lsp.enable` | lspconfig.setup | 0.11+ 官方推荐方式，一行启用 |
| 文件搜索 | fzf-lua | telescope / mini.pick | 习惯 fzf + 高性能 |
| 文件管理 | oil.nvim | neo-tree / nerdtree | 以 buffer 编辑，符合 Vim 哲学 |
